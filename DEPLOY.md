# Deployment

This is a static site. `index.html` is the interactive Air India Holidays demo
homepage — entry point and landing page in one, no proposal-page swap.

`node build.mjs` produces a deployable **`dist/`**:

- only files reachable from `index.html` are included (unused assets, backend
  code under `infrastructure/`, etc. are dropped — catalog JSON and itinerary
  JS are force-included regardless)
- `_headers` and `robots.txt` are copied in, and every page carries a
  `noindex` meta tag

Build output is git-ignored — it is generated by CI on each deploy.

This is a concept/demo build for Air India + Tata Group (Cricket World Cup 2027
and Taj Holidays packages), adapted from easyGDS's original Ethiopian Holidays
RFP build. It runs entirely in `mockMode` off local catalog JSON — no AWS
Lambda backend or OpenRouter API key is needed to view or share it.

## Local preview

```bash
node build.mjs        # writes ./dist
npx serve dist        # or: python3 -m http.server -d dist 8080
```

## Cloudflare Pages (Git integration)

Connect this GitHub repo to a **new** Pages project and set:

| Setting                  | Value          |
| ------------------------ | -------------- |
| Framework preset         | None           |
| Build command            | `node build.mjs` |
| Build output directory   | `dist`         |

Response headers (incl. `X-Robots-Tag` noindex + security headers) come from
`dist/_headers`. `pages_build_output_dir` is also declared in `wrangler.toml`.

> A Pages project is either "direct upload" or "Git connected" — it can't be
> both. Create a new Git-connected project, or deploy manually with:
> `npm run build && npx wrangler pages deploy dist --project-name=air-india-holidays --branch=main`

## AWS Amplify Hosting

`amplify.yml` is committed, so just connect the repo. Amplify runs
`node build.mjs` and publishes `dist/`. The `noindex` + security response
headers are applied via the `customHeaders` block in `amplify.yml`
(Amplify does not read `_headers`).

## Search-engine hardening

Indexing is disabled three ways: `X-Robots-Tag` response header (all files),
`<meta name="robots">` on every HTML page, and `robots.txt` (`Disallow: /`).
These are advisory to well-behaved crawlers — for true access control put
Cloudflare Access / Amplify Access (auth) in front of the site.
